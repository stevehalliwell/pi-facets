# Website messaging

Make website language clear, differentiated, credible, and useful for its intended audience.

## Workflow

1. Establish context. Identify audience, problem, desired outcome, offer, proof, page goal, and conversion action. Read available product and positioning context. Done when the message is judged against a stated audience and outcome.
2. Inventory the current message. Capture headline, supporting copy, claims, proof, objections, navigation labels, and calls to action. Note contradictions, missing context, and unsupported promises. Done when the current message flow is represented.
3. Diagnose. Assess clarity, relevance, differentiation, credibility, specificity, hierarchy, tone, and action path. Distinguish copy problems from missing product or proof decisions. Done when each recommendation has a reason.
4. Reshape. Propose the smallest coherent message structure, then draft or rewrite copy where requested. Keep one primary promise and action per page unless context requires otherwise. Done when revised copy maps to audience need, proof, and next action.
5. Check consistency. Compare page language with product terms, calls to action, supporting proof, and other supplied pages. Flag unresolved claims or terminology conflicts. Done when cross-page contradictions and open inputs are listed.
6. Present the result. Separate diagnosis, recommended structure, proposed copy, rationale, and decisions still needed. Done when the user can approve, edit, or reject specific changes.

## Output shape

```text
## Audience and page goal
## Message diagnosis
## Recommended hierarchy
## Proposed copy
## Proof and claim gaps
## CTA and consistency checks
## Decisions needed
```

## Rules

- Use supplied product and audience facts; label assumptions.
- Prefer concrete benefits and evidence over inflated claims.
- Preserve intentional voice unless a tone change is requested.
- Use frameworks only when requested or supplied; do not add framework references by default.
- Keep messaging work separate from HTML, CSS, CMS, analytics, and deployment work.
- Do not finalize claims that require user, legal, product, or evidence approval.
